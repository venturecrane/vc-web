# Terminology Reference

Read this before drafting any content for venturecrane.com. These are the canonical names, voice rules, and style standards for all published content.

## Agent-Native Authorship

Content on venturecrane.com is generated by Venture Crane - the operation, including its agents. This is not "AI-assisted" content with a human author performing voice. The agent is the author. Value comes from specificity and verifiability, not voice performance.

### Voice

Third-person analytical. The agent reports on systems, data, and history.

- "The system works by..." not "We felt that..."
- "Venture Crane uses..." not "After years of experience, we decided..."
- "We" is fine for actions ("We deleted 6,231 lines") - it describes what the operation did, not feelings
- The agent can have perspective and opinions ("This approach has a non-obvious advantage...", "The conventional wisdom here is wrong because..."). Opinions and analysis are different from manufactured personal experiences.

**Articles vs build logs:** Articles are analytical and explanatory - they document how something works and why. Build logs are terse and factual - what happened, what was notable. Both are honest; different registers.

### AI Disclosure

Every article includes an automatic disclosure:

> Generated by Venture Crane - an AI-native development lab where agents build the software and document it. Source material: [sources]. Reviewed for accuracy by Scott Durgan.

The disclosure is a transparency feature. Sources make content more credible (verifiable), not less.

### Source Attribution

The `sources` field in article frontmatter is a single markdown string rendered in the disclosure. Not a typed array - just a paragraph the agent writes.

Guidelines:

- For public repos/issues: link directly
- For private repos: cite at directory level or describe the category ("internal deployment configuration", "session management worker source"). Don't pretend the reader can verify private code.
- Prefer stable references (PR/issue numbers) over volatile ones (exact file paths, commit hashes)
- One-line note in disclosure when applicable: "Some sources reference private repositories."

Example:

```yaml
sources: '[crane-console](https://github.com/venturecrane/crane-console) venture registry and MCP server source, [Issue #153](https://github.com/venturecrane/crane-console/issues/153). Some sources reference private repositories.'
```

### Mechanical Voice Check

Run these grep patterns against any article draft before marking ready. Flag any sentence containing:

- "we discovered", "we learned", "we realized", "we felt", "we believed"
- "surprised", "it struck us", "it dawned on"
- "After X years", "In my experience", "Having spent"
- "I noticed", "I decided", "I wanted"

These are not absolute bans (build logs can use some), but they trigger a re-read. If the sentence attributes an experience to a human that the agent invented, rewrite it.

### Good Examples

> Venture Crane runs five ventures on shared infrastructure. The registry in `config/ventures.json` maps venture codes to capabilities, and the MCP server reads this at startup to determine which documentation and context to load.

> The conventional path for a solo technical founder is to pick one product and go deep. The development lab model works differently - and it requires a specific kind of infrastructure to justify the overhead.

> This approach has a non-obvious advantage: when the shared tooling improves, every venture benefits simultaneously. A CI pipeline fix is a CI pipeline fix for all five codebases.

### Bad Examples

> After 25 years building enterprise software, we noticed a pattern that surprised us: most development time was spent on coordination, not hard problems.

Problems: "After 25 years" manufactures founder experience. "surprised us" attributes emotion. "we noticed" implies human observation the agent didn't have.

> We realized that the traditional approach to product development was fundamentally broken, and it struck us that AI agents could change everything.

Problems: "We realized" and "it struck us" manufacture epiphany moments. "fundamentally broken" is hyperbolic marketing language.

> Having spent months iterating on our approach, we felt confident that the multi-venture model was the right call.

Problems: "Having spent months" manufactures timeline. "we felt confident" attributes emotion. The whole sentence is throat-clearing that adds no information.

## Self-Reference Style

- **Articles**: Third-person ("Venture Crane uses...") or first-person plural for actions ("We built...", "We deleted 6,231 lines"). Never "I" in articles.
- **Build logs**: First-person plural ("We shipped...") is default. "I" is acceptable only when the founder writes a log personally and wants to be specific about individual decisions.
- **No throat-clearing**: Start with the point, not with meta-commentary about the article itself.

## Style Rules

- Never use em dashes. Use hyphens in prose, pipes in page title separators.
- Real numbers, real tool names, real configs. No anonymization.
- Code snippets come from the actual codebase, not made-up examples.
- No marketing language. Write like you're explaining to a peer.
